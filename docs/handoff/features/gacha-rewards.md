# 写字台多部件奖励

索引：`docs/handoff/README.md`

## 奖励规则

成功组成汉字时，按本题实际消耗的部件数发放 Cris：

| 部件数 | 奖励 |
| --- | --- |
| 1–2 | 0 |
| 3 | 2 |
| 4 | 5 |
| 5 | 10 |
| 6+ | 20 |

规则实现为 `src/game/gacha.ts` 的纯函数 `gachaWordReward()`。奖励在提交答案
通过 `GachaDrawer.findSubmission()` 后立即写入 `CrisStore`，与抽卡的 20 Cris
消费相互独立。

## 卡片槽位提示

- “第一张卡片”指本次拆法消耗的卡片中，在 `cardSlots` 内索引最小的一张，
  即视觉上从上到下、从左到右最先出现的位置。
- 已用卡片完成淡出后，奖励元素占据该卡片的原网格槽位，不使其它卡片重排。
- 元素显示红色 `[Cris 图标]+N`；正常进入、停留后退场，随后整个手牌重绘为
  空槽。`prefers-reduced-motion` 下跳过卡片槽动画，但奖励仍会立即计入余额。

## 结算反馈

- 抽选结果标题下方显示本次所有成功组字的奖励总和，格式为
  `[Cris 图标]+N`，复用挑战结算的 `.result-cris` 视觉语言。
- 没有奖励时不显示该行。
- “结算本轮”位于抽得卡片区右上角，是不带独立边框的横向红色渐变条：
  左端透明、右端主题红，右缘与五列卡片网格右缘对齐。
- 按钮占据卡片区预留的顶部空间，不覆盖卡片；其下与第一排卡片保留间距。
- 发牌动画和正式手牌共享 `--gacha-card-top-space`，保证动画结束切换 DOM 时
  卡片位置、尺寸不跳动；按钮高度也从这段空间派生。

## 验证

- `tests/gacha.test.ts` 覆盖 1、2、3、4、5、6、9 部件的奖励阈值。
- Playwright 实测 3 部件答案：顶部余额由 1000 扣至 980 后增加至 982，
  奖励槽位于第一张已用卡位置，结算总额为 `+2`。
- `npm test`、生产构建、主流程 smoke 和全部视口检查通过。
