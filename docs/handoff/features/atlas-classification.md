# 图鉴部件分类

索引：`docs/handoff/README.md`

## 可渲染条件

- 单字符名称可以直接显示。
- 多字符名称必须有 SVG 资源兜底。
- 多字符且无 SVG 的部件不参与题目或图鉴生成。

## 关联字分类

普通通规关联字：

- 属于通规字表，并且可由正常拆分流程生成的汉字。

EX 关联字：

- 不属于通规字表，但不属于 XR 所述不可达情况的汉字。
- 通常会进入挑战模式 EX 阶段。

不可达关联字：

- 单部件字。
- 通规外双部件字。
- 通规外多部件字，但拆分中包含不可渲染部件。

## 部件等级

1. 如果一个部件的所有关联字都不可达，则此部件为 XR。
2. 如果部件不是 XR，且只在 EX 关联字中出现，则它是 EX 部件。
3. EX 是附加属性，不取代稀有度。
4. EX 部件的稀有度按 `EX 关联字数量 / 10` 套用通用稀有度阈值。
5. 其它部件的稀有度按普通通规关联字数量计算。

## 完成度里程碑

| 稀有度 | 里程碑 |
| --- | --- |
| N | 15%、30%、60% |
| R | 15%、30%、60% |
| SR | 30%、60% |
| SSR | 2 个通规关联字时为 100%；更多关联字继续动态计算 |
| UR | 100% |
| XR | 不计算完成度 |

SSR 的 2 字特例不再使用原来的 50% 动态阈值。UR 保持原有完成度分母，
即普通 UR 的单个通规关联字仍可达到 100%。

## 代码结构整理

- `GameData` 使用统一的 `ComponentDefinition` 目录，集中保存 ID、名称、SVG 和
  `renderable` 状态。
- 图鉴生成器把字符关系统一标记为 `regular`、`ex`、`unreachable`、`self`，
  不再混用“可绘制字符”和“可出题字符”两个概念。
- 多字符部件先通过资源可渲染性检查，再计算 EX/XR 和稀有度。
- 已移除“所有未收录资源一律作为 XR”的兜底；没有关联字的资源不会伪造图鉴条目。

## 当前验证

| 部件 | 名称 | 结果 |
| --- | --- | --- |
| 182 | 𠂢心 | SR，普通部件；使用 `182N.svg` |
| 265 | 肅心 | SSR-EX，22 个 EX 关联字 |
| 314 | 臦偏 | UR-EX，2 个 EX 关联字 |

生成脚本位于 `scripts/build-atlas-index.mjs`。多字符部件不能因为名称长度被提前排除；
必须先应用可渲染条件，再计算 EX/XR 与稀有度。
