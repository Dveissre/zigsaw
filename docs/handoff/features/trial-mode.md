## 已确认规则

- 共 7 个阶段。
- 每阶段道中题数由当前进阶决定，随后 1 道守幕；进阶 0 为 7+1，进阶
  1 起为 8+1。
- 无制限普通题 30 秒，BOSS 90 秒；规则与进阶可继续修正时限。
- 进阶 0–1 的三星制限在规则自身时限上再乘以 1.3；进阶 2 起取消。
  进阶 4 起一、二星制限再乘以 0.7，零星级与三星不受该惩罚。
- 使用通规一级、二级汉字。
- 普通题部件数概率：2 部件 15%、3 部件 42%、4 部件 23%、
  5+ 部件 20%。当前字库足够，不触发现有长拆法稀疏补偿。
- 无制限 BOSS 使用 6–8 张部件卡组成两个不同汉字。
- 无制限 BOSS 单字允许 2–6 部件，两字合计必须为 6–8 部件；
  规则可改变答案数量和总卡数。
- BOSS 答案不要求组成词语，但彼此不允许相同。
- 可以一次提交多个合法答案，也可以逐字提交并继续。
- 分步提交会立即移除第一个字使用的卡；此时可以撤销并恢复全部卡。
- 已消耗的卡保留空槽位，不重排其它卡片。
- BOSS 卡片分行固定为 6→3+3、7→4+3、8→4+4、9→5+4、10→5+5；
  单行内部禁止再次换行，不随缩放改变分组。
- BOSS 部件区右上角以斜线分数显示已成功组成的字数；错误提交不计数，
  撤销会减一。
- 已提交内容按字分行，每行以“部件卡｜汉字｜撤销图标”展示，可逐行撤回。
- BOSS 的答案揭示与结算回顾优先保留已提交的正确答案或正确解的一部分；
  该提交排在其所属正确解的前部。
- BOSS 揭晓只显示一组完整正确解，不混入没有补全为正确解的提交。若玩家提交
  过某个正确解中的答案或其一部分，优先显示包含该提交的正确解；否则任取
  一组正确解。该选择逻辑在会话层统一执行，覆盖普通组件、奇境、厄境、回声室、
  通配符、复沓与格式塔等 BOSS。
- “繁缛”守幕和普通组件 BOSS 一样按当前卡组接受所有合法可组答案，不要求
  提交题目预生成的两个目标答案；生成仍固定为两个五部件字、共 10 张卡。
- 已消耗卡片保留固定槽位并变淡，其他卡片不重排。
- BOSS 顶部信息条首次进入时铺红并保持到 BOSS 结束，反馈刷新不重播。
- 游戏信息栏左端显示当前制限徽记。徽记复用开始页的径向墨晕、左上/右下直角、
  右上竖排红色四角星；手机为 38px，电脑端为 47px 以对齐信息栏左侧竖条高度。
  BOSS 红底只覆盖进度标题，避免吞掉红色星级。
- 超时或中止后先揭晓答案。失败页提供“结算”和与答题操作栏同款的“换题”：
  还有额度且规则允许换题时，消耗一次换题并重新生成当前题面，不推进题号；
  额度耗尽或规则禁用换题时“换题”置灰。全局调试或试炼专用调试权限会额外
  显示免费的“继续”。使用换题复活时，本次超时或弃权不计入失败历史，之后
  完成整局仍可获得“雾径得津”。
- 手机宽度下，BOSS 的斜线分数移到提交键右侧绝对定位，不参与输入框和提交键
  的排版。`390×430` 键盘后视口已验证 10 张卡、两条提交记录不会挤压输入区，
  页面无滚动或横向溢出。
- 换题次数使用整场试炼共享的单一计数。进阶 0 初始 3 次并每完成 2 幕
  增加 1 次；进阶 1–2 初始 3 次并每完成 3 幕增加 1 次；进阶 3 起初始
  1 次并每完成 3 幕增加 1 次。换题只重新生成当前题号下的题目，不推进关卡；
  最后一题换题后仍停留在最后一题，守幕换题后仍停留在当前守幕。回声室通过
  `allowSkip: false` 禁用换题。
- 首页只有进阶 0 显示完整的题数、时限和换题基础规则；进阶 1–4 只显示相对
  上一阶的变化。当前可解锁上限为 4，进阶 5–7 的说明区只显示“尚未开放”。
- 首次通关进阶 0–3 后，结算页的 Cris 行追加“已解锁进阶N”；重复通关不显示。
  进阶 4 是当前上限，通关后不追加下一阶解锁提示。
- 允许暂停。`/test/` 中沿用暂停时将剩余时间减半的测试行为。
- 暂停时圆环轨道闪红；恢复时卡片使用揭开动画。
- 阶段开始页从第二幕起同时显示“进入”和“结算”；主动结算使用标题
  “临歧何反”。自然失败显示“覆鹿遗蕉”；使用过换题后通关显示“雾径得津”，
  全程未使用换题通关显示“知我梦中”。
- 四个结果标题分别把“鹿”“歧”“津”“梦”显示为主题红色。结算页不显示平均
  用时。
- 结算页“分享”位于“再次试炼”和“返回”之间，复用挑战模式的复制与 Toast
  流程。试炼分享按结果标题、结束幕次、当前幕制限、最近两幕题序生成。
- 不保存中途进度；刷新或退出后不恢复本局。
- 遇到的汉字进入图鉴。
- Cris 奖励在结算时一次性发放。进阶 0–4 的完整通关基准为
  `100 / 150 / 180 / 220 / 280`；“知我梦中”额外乘 1.2。
- 未完整通关时按已完整通过的上一守幕计算：0、1 幕为 0%，2 幕为 3%，
  3 幕为 8%，4 幕为 18%，5 幕为 32%，6 幕为 50%。进阶 1 的部分奖励
  因此为 `0 / 0 / 5 / 12 / 27 / 48 / 75`，完整通关为 150。

## 规则数据

完整规则目录、依赖、实装批次和候选池分析见
`docs/trial-rules-plan.md`。原始意见表归档在 `docs/archive/`。
代码分层、退役规则约束与测试流程见
`docs/trial-architecture.md`。

- `public/data/trial-rules.json` 是规则的权威数据，与显示名称解耦。
- 规则使用稳定 ID：`unrestricted`、`tetrarchy`、`presto`、
  `reschedule`、`inspissation`、`byland-water`、`byland-herb`、
  `byland-mount`、`byland-people`、`byland-speech`、`outland-water`,
  `outland-herb`、`outland-mount`、`outland-people`、`outland-speech`、
  `hallraum`、`nuncupation`、
  `abscission`、`reductionism`、`prefabrication`、`wildcard`、
  `polydactyly`、`selcouth`、`gestalt`、`minimalism`、`myopia`、
  `compages`、`aphantasia`。
  中文名、英文名、说明和星级可以独立修改。
- 图标位于 `public/assets/trial-rules/<id>.svg`，文件名必须与规则 ID
  一致。
- 规则 JSON 使用 v3 结构，并分为：
  - `description.public`：玩家实际看到的准确说明；
  - `description.debug`：仅调试模式显示的参数化说明，不包含文件依赖和内部实现；
  - `description.internal`：开发用完整效果；
  - `timing`：普通题与 BOSS 的基础时限和倍率；
  - `selection`：普通题和 BOSS 的部件数、答案数与总卡数约束；
  - `policy`：题面来源、判题兼容口径和展示卡形态。
- `src/game/trial-rules.ts` 在加载时校验 v3 文档、阶段星级池及关键枚举值；
  无效规则不会被静默降级。
- `src/game/trial-runtime-data.ts` 集中声明规则依赖的拼音、繁简、格式塔、
  词池和扩展答案数据，并负责按需加载；页面不再维护规则专属数据加载分支。
- 普通题可通过 `partWeights` 指定固定长度权重，或通过
  `partWeighting: "pool"` 按当前题库分布抽取。
- 简赅使用 `2:3 = 1:1`；繁缛按五部件以上的实时题库分布抽取。
- 每局开始时按 `stageStars` 预生成七幕规则：0 / 1 / 1 / 2 / 2 / 2或3 / 3。
  同一局内优先不重复规则；第六幕先等概率决定二星或三星，再从对应星级抽取。

调试解锁后，阶段开始页会显示“覆写”选择器。选择结果保存在
`TrialState.forcedRuleId`，只覆盖当前幕的题库、时限、BOSS 结构与卡片策略；
进入下一幕时自动清空并恢复该局预生成的幕规则。选择“默认”可立即撤销当前幕
的覆盖。

左上角调试入口在首页、阶段页、游戏页和结算页均显示。若在计时游戏中首次
请求口令，游戏会先暂停，口令框关闭后再恢复；在阶段页解锁或撤销时会立即
刷新制限选择器。

调试权限分为两级：

- 全局调试密钥：在主页、图鉴、写字台和各游戏模式中有效，允许修改 Cris。
- 试炼专用密钥：只在存在进行中的试炼会话时有效，允许查看调试文案和覆写本幕
  制限，不开放 Cris 编辑；离开试炼后立即失效。

调试制限下拉框按星级从低到高排序。控件只保留“覆写”标题与规则选择，
默认项显示为“默认”。

## 模式入口

- 正式页模式：挑战、练习。
- `/test/` 模式：挑战、试炼、练习。
- 试炼首页的“进阶”控件为 0–7 Center-focus Carousel：当前数字居中并带左右
  尖括号，两侧数字逐渐缩小、变淡并轻微虚化；支持点击、拖拽、触摸滑动和
  方向键。初始仅解锁进阶 0；任一完整通关会把下一进阶解锁。已通关项在右上
  显示四角星：普通通关为紫色，未使用换题的完美通关为金色；完美通关项的数字
  本身也固定为金色，失焦后不退回紫色。锁定项仍可滑动查看但开始键显示
  “未解锁”并禁用。默认焦点
  为当前最大已解锁进阶。
- “无尽”不再是独立模式按钮，而是练习模式内的开关。
- “无尽”开关位于题数行最右侧；开启后题数控件不隐藏，而是置灰禁用。
- 试炼入口在测试页的挑战和练习之间。
- 游戏和结算界面使用“第一幕”至“第七幕”；“阶段”仅作为内部或
  口头讨论用词。

## 规则前置数据层

- `TrialState.timeLimit` 保存当前题的原始时限。普通题和 BOSS 不再由
  界面根据阶段临时套用常量；计时环、平均用时和超时结算都读取该字段。
- 普通题的 `TrialQuestionState` 分离为：
  - `answerWay`：标准答案拆法。
  - `displayCards`：实际展示的带 UID 卡片，当前 `source = "answer"`。
- BOSS 的 `TrialBossState` 同时保存 `expectedWays` 与
  `initialCards/cards`，分别表示标准拆法和实际可操作卡片。
- 历史记录保存 `answerWay`、`displayCards`、标准部件名和展示部件名，
  供规则产生干扰卡、隐藏卡或万能牌后继续正确回放。
- 遮挡目标在出题时随机确定，并记录为卡片的 `obscuredAtMs`。累计有效
  答题时间达到阈值后设置 `obscured`；暂停冻结计时，恢复后不还原已翻黑卡。
- 翻黑通过 `obscure` 会话事件原地更新对应卡片的 DOM，不重绘整个游戏页，
  因此不会替换输入框或打断输入法候选栏。
- 翻黑卡从 DOM 移除字符、部件 ID 和可复制文本，但仍保留在会话卡片模型中，
  因而继续参与判题和答案消费。

## BOSS 验证

- 每次提交会搜索当前卡片中与规则允许部件数一致的切分，并验证所有
  已提交答案。
- 分步提交时，先接受任何能由当前卡片组成的合法答案，不预判剩余卡片
  是否还有解；玩家可随时撤回错误选择。
- 规则要求数量的答案全部提交后，只有答案卡全部耗尽才进入下一阶段。
  若仍有答案卡剩余，则显示错误反馈并停留在 BOSS，让玩家撤回后重试。
- 所有答案必须不同。
- 答案判定复用 `GameData.accepted()`，包括单向答案兼容展开。
- BOSS 结算作为一题记录，保存全部答案和完整部件顺序。
