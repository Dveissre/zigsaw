# 试炼模式

索引：`docs/handoff/README.md`

## 状态

- 白模已完成，仅在 `/test/` 显示“试炼”入口。
- 正式 `/` 暂不显示试炼入口。
- 已接入无制限、四分法、急板、失与得、拾级、五个奇境变体、指差确认、
  三秋树、化约论、预制件、构词法、半韵法、复沓、通配符、枝指、茁轧、
  格式塔、极简主义、短视、繁缛、心盲症共二十五条规则定义。
- 已完成制限接入前的三项数据层准备：每题时限状态化、标准拆法/
  展示卡分离、规则兼容题库可用性预检。
- 实现位于 `feature/trial-mode`，未提交或推送时以 `git status` 为准。

## 已确认规则

- 共 7 个阶段。
- 每阶段 8 道普通题，随后 1 道 BOSS。
- 无制限普通题 30 秒，BOSS 90 秒；规则可覆盖时限。
- 使用通规一级、二级汉字。
- 普通题部件数概率：2 部件 15%、3 部件 42%、4 部件 23%、
  5+ 部件 20%。当前字库足够，不触发现有长拆法稀疏补偿。
- 无制限 BOSS 使用 6–8 张部件卡组成两个不同汉字。
- 无制限 BOSS 单字允许 2–6 部件，两字合计必须为 6–8 部件；
  规则可改变答案数量和总卡数。
- BOSS 答案不要求组成词语，但彼此不允许相同。
- 可以一次提交多个合法答案，也可以逐字提交并继续。
- 分步提交会立即移除第一个字使用的卡；此时可以撤销并恢复全部卡。
- 已消耗的卡保留空槽位，不重排其它卡片。
- BOSS 部件区右上角以斜线分数显示已成功组成的字数；错误提交不计数，
  撤销会减一。
- 已提交内容按字分行，每行以“部件卡｜汉字｜撤销图标”展示，可逐行撤回。
- BOSS 的答案揭示与结算回顾按提交顺序排列；若只提交了部分答案就结束，
  已提交答案排在前，其余答案按题目顺序补在其后。
- 已消耗卡片保留固定槽位并变淡，其他卡片不重排。
- BOSS 顶部信息条首次进入时铺红并保持到 BOSS 结束，反馈刷新不重播。
- 超时立即结束试炼。
- 允许暂停。`/test/` 中沿用暂停时将剩余时间减半的测试行为。
- 暂停时圆环轨道闪红；恢复时卡片使用揭开动画。
- 中止或超时后先以红字揭晓答案，再由玩家点击“结算”进入结果页。
- 不保存中途进度；刷新或退出后不恢复本局。
- 遇到的汉字进入图鉴。
- Cris 奖励预留了结算字段和发奖入口，数值尚未确定；白模结算显示
  “奖励待定”，当前不实际增加 Cris。

## 规则数据

完整规则目录、依赖、实装批次和候选池分析见
`docs/trial-rules-plan.md`。原始意见表归档在 `docs/archive/`。

- `public/data/trial-rules.json` 是规则的权威数据，与显示名称解耦。
- 规则使用稳定 ID：`unrestricted`、`tetrarchy`、`presto`、
  `reschedule`、`inspissation`、`byland-water`、`byland-herb`、
  `byland-mount`、`byland-people`、`byland-speech`、`nuncupation`、
  `abscission`、`reductionism`、`prefabrication`、`wildcard`、
  `polydactyly`、`selcouth`、`gestalt`、`minimalism`、`myopia`、
  `compages`、`aphantasia`。
  中文名、英文名、说明和星级可以独立修改。
- 图标位于 `public/assets/trial-rules/<id>.svg`，文件名必须与规则 ID
  一致。
- 规则 JSON 使用 v2 结构，并分为：
  - `description.public`：玩家实际看到的准确说明；
  - `description.internal`：开发用完整效果；
  - `timing`：普通题与 BOSS 的基础时限和倍率；
  - `selection`：普通题和 BOSS 的部件数、答案数与总卡数约束；
  - `policy`：题面来源、判题兼容口径和展示卡形态。
- `src/game/trial-rules.ts` 在加载时校验 v2 文档、阶段绑定及关键枚举值；
  无效规则不会被静默降级。
- 普通题可通过 `partWeights` 指定固定长度权重，或通过
  `partWeighting: "pool"` 按当前题库分布抽取。
- 极简主义使用 `2:3 = 1:1`；繁缛按五部件以上的实时题库分布抽取。
- 当前测试档期写在 `stageAssignments`：
  - 第一幕：无制限。
  - 第二幕：四分法。
  - 第三幕：急板。
  - 第四幕：极简主义（测试页临时排期）。
  - 第五幕：短视。
  - 第六幕：繁缛。
  - 第七幕：心盲症。

调试解锁后，阶段开始页会显示“强制制限”选择器。选择结果保存在
`TrialState.forcedRuleId`，只覆盖当前幕的题库、时限、BOSS 结构与卡片策略；
进入下一幕时自动清空并恢复 `stageAssignments` 中的默认规则。选择
“按幕次”可立即撤销当前幕的覆盖。

左上角调试入口在首页、阶段页、游戏页和结算页均显示。若在计时游戏中首次
请求口令，游戏会先暂停，口令框关闭后再恢复；在阶段页解锁或撤销时会立即
刷新制限选择器。

| --- | --- |
| `src/game/trial.ts` | 独立 `TrialSession`、题目池、BOSS 与计时 |

| `public/data/trial-rules.json` | 规则名称、星级、图标与效果数据 |
| `src/main.ts` | `/test/` 入口、阶段提示、游戏页和试炼结算 |
| `src/styles.css` | 模式开关、阶段提示、BOSS 与试炼结算样式 |

试炼没有继续塞入 `GameSession`。后续阶段制限也应作为声明式规则接入
`TrialSession`，避免继续增加挑战模式的模式分支。

## 模式入口

- 正式页模式：挑战、练习。
- `/test/` 模式：挑战、试炼、练习。
- “无尽”不再是独立模式按钮，而是练习模式内的开关。
- “无尽”开关位于题数行最右侧；开启后题数控件不隐藏，而是置灰禁用。
- 试炼入口在测试页的挑战和练习之间。
- 游戏和结算界面使用“第一幕”至“第七幕”；“阶段”仅作为内部或
  口头讨论用词。

## 规则前置数据层

- `TrialState.timeLimit` 保存当前题的原始时限。普通题和 BOSS 不再由
  界面根据阶段临时套用常量；计时环、平均用时和超时结算都读取该字段。
- 普通题的 `TrialQuestionState` 分离为：
  - `answerWay`：标准答案拆法。
  - `displayCards`：实际展示的带 UID 卡片，当前 `source = "answer"`。
- BOSS 的 `TrialBossState` 同时保存 `expectedWays` 与
  `initialCards/cards`，分别表示标准拆法和实际可操作卡片。
- 历史记录保存 `answerWay`、`displayCards`、标准部件名和展示部件名，
  供规则产生干扰卡、隐藏卡或万能牌后继续正确回放。
- 遮挡目标在出题时随机确定，并记录为卡片的 `obscuredAtMs`。累计有效
  答题时间达到阈值后设置 `obscured`；暂停冻结计时，恢复后不还原已翻黑卡。
- 翻黑通过 `obscure` 会话事件原地更新对应卡片的 DOM，不重绘整个游戏页，
  因此不会替换输入框或打断输入法候选栏。
- 翻黑卡从 DOM 移除字符、部件 ID 和可复制文本，但仍保留在会话卡片模型中，
  因而继续参与判题和答案消费。
- 失与得按幕维护共享时间池。普通题与 BOSS 都读取同一剩余值；答对后加
  5 秒并封顶 150 秒，进入下一幕时重新初始化为 150 秒。该规则暂停固定
  扣除 15 秒，覆盖测试环境默认的半时罚则。
- 拾级在进入阶段时生成整幕八题部件数路径。路径起点为 2，终点随机为 7
  或 8，只能不下降或单步增加 1；普通题依次按路径取题。BOSS 固定总卡数
  为 10，可分给两个不同答案。
- 终点先按 7/8 各自可用答案数加权；停留位置再按被重复长度的可用答案数
  加权。因此终点和停留位置都会随各部件数实际池体量倾斜，而不是固定等概率。
- 最近 12 个 7/8 部件汉字记录在
  `localStorage["zigsaw.trial.inspissation.recentLongChars"]`，新局优先
  避开这些答案；仅在候选池耗尽时回退。
- 奇境变体通过 `selection.excludedComponents` 排除整个成员类别；题面拆法
  使用逐拆法过滤，不只看整字是否仍有一条合法拆法。
- 普通题按 `decoyCount: 1` 加入一张 `source = "decoy"` 卡，BOSS 加入两张
  互不相同的干扰卡。允许干扰卡与答案卡组成其他汉字，但提交这些字判错。
- 正确答案揭示时，答案卡继续铺绿；干扰卡同时不铺绿、淡出并轻微模糊，
  原卡槽保留，避免其他卡重排。
- BOSS 判题只接受本题目标答案；`mustIgnore` 干扰卡允许剩余，不要求被答案
  消费。
- 指差确认懒加载 `public/data/hanzi_pinyin12.json`，按 `plain` 读音判题，按
  `marked` 读音揭示。输入统一转换为小写并令 `ü/v` 等价；BOSS 同时提交
  多个拼音时以空白分隔。
- 三秋树懒加载 `public/data/tongyong12_trad.json`，只收一、二级简体字中
  至少存在一条二部件以上繁体拆法的映射。展示繁体拆法，普通题和 BOSS 的
  提交使用对应简体字；答案揭示显示“繁体—简体”，结算卡使用繁体在左上、
  简体在右下的斜切配对样式，元信息仍按简体字居中。题目出现时简体和繁体
  会同时登记到图鉴；单部件映射不进入题池。
- 化约论从答案兼容层中查找恰好包含两个可渲染部件的直接展开方案。普通题在
  选中答案拆法后替换一个来源部件，并以展开后的卡组重新计算接受答案；BOSS
  两个答案各替换一个来源，允许任意不重复的兼容答案切分。来源部件按幕去重，
  普通题和 BOSS 共用同一集合。
- 预制件从 `char_sym.json` 全字表直接两部件拆法中选择提示字，不经过答案
  兼容层。普通题按 3:4:5:6:7:8:9 = 30:45:17:6:1.5:0.4:0.1 的权重抽题，
  每题把来自答案的一对卡替换成黄色复合卡。BOSS 原始共 8–10 个部件，跨两个
  答案选择两组互不重叠的卡预组，显示为 6–8 张。复合卡内部保存原组件，
  可被两个答案分别消费；提示汉字按幕去重。逐字提交时先接受任何由当前组件
  构成的合法答案，不预判剩余卡是否已有解；第二次提交时才校验完整两答与
  全部组件耗尽。
- 预制件的非 BOSS 卡使用浅黄色底；结算回顾使用低透明度黄色底。BOSS 中
  只消费了部分内部组件的复合卡以中间透明度显示。
- 构词法懒加载 `public/data/composition-words.json`。该文件由
  `docs/words_2to4.txt`、当前拆字表和兼容层生成，词池允许一部件字。
  普通题使用合计恰好 4 卡、字数为 2 的词；BOSS 使用合计 6–8 卡、字数为
  3–4 的词。判题会把完整词逐字分配为互不重叠的卡组，并通过答案兼容层
  接受同卡组的其他合法词。BOSS 支持整词提交和按词序逐字提交。
- 构词法在普通题池与 BOSS 池内分别统计汉字次数；词权为
  `1 / 词内各字在所属候选池中出现次数的几何平均数`，用于降低池内高频字词
  的占比。
- 半韵法使用独立词池 `public/data/assonance-words.json`，排除含重复汉字的
  词。只有跨至少两个字的同名词元才合并为隐藏数量卡；仅单字内重复的词元仍
  显示为多张普通卡。道中压缩后为 4–5 卡且至少 1 张跨字复沓卡，BOSS 为
  6–10 卡且至少 2 张跨字复沓卡。复沓卡不显示乘数、颜色或辅助标签。
- 半韵法判题按可见卡数匹配兼容层拆法；一张单卡可被解释为普通卡或至少两份
  的跨字复沓。BOSS 支持整词提交和按词序逐字提交。
- `npm run build` 与 `npm run dev` 会运行 `build:composition-pools`，同步
  更新构词法与半韵法词池。
- 复沓按 `symbolId` 合并一个答案拆法中的全部同名词元，并以青色数量卡显示
  剩余 `×n`；合并后少于两张卡的拆法排除。BOSS 将两个答案的全部词元一起
  合并，要求合并卡池为六至八张、至少两张复沓卡，且至少一个复沓符号跨两个
  答案出现；不要求两个答案各自含有重复词元。普通题将恰好两张卡的拆法权重
  降至 0.2，并在道中隐藏乘数；判题接受所有普通卡均被使用、且每张复沓卡
  至少取 2 份的答案，不要求耗尽原始份数。结算按实际答案重建数量卡并显示
  对应乘数。BOSS 判题按组件份数消费，数量卡可分两次使用；部分消费后保留
  槽位并降低不透明度。
- 通配符把答案拆法中的一个来源卡替换为白板；生成阶段只按直接拆法保留候选
  答案集合恰好为一字的题，BOSS 两个答案各替换一张白板。判题时重新枚举全部
  可渲染部件并应用答案兼容层，因此兼容层形成的预期外汉字也会接受；提交记录
  中的白板继续显示 Cris 图标。白板沿用普通卡样式并严格居中显示黑色图标，
  DOM 不暴露真实来源 ID。
- 通配符 BOSS 在某个答案存在多条兼容拆法时，会继续回溯尝试后续分支，优先
  采用能耗尽全部答案卡的分配。局部合法但未耗尽的只作为兜底结果，不会抢先
  阻止另一条完整解通过。
- 枝指的数据层按 `component-usage` 口径计算 N 级部件关联字集合，并按关联字数
  加权抽取。普通题加入 1 张、BOSS 加入 2 张不同干扰卡；加入前仅检查移除一个
  原答案部件后补入干扰卡的组合，若其形成合法汉字则拒绝候选，更小组合不参与
  该检查。干扰卡裸卡样式与普通卡一致，仅在答案揭示时执行既有的淡出处理；
  BOSS 可保留干扰卡完成。
- 茁轧通过规则的 `selection.levels` 限定二级、三级通规字；运行时候选题库
  已扩展到三级字，但默认规则仍只取一、二级。
- 格式塔懒加载 `public/data/gestalt-pairs.json`。生成池中的部件对和答案必须
  由同一条原始拆法直接覆盖；兼容层不能扩充生成池。池排除指定部件及自身可
  直接成字的整对，生成答案按字符去重并限制为最多 3。判题时改用答案兼容
  展开：提交字的拆法只要能展开到同时包含线索卡即可通过，因此允许生成池之外
  的兼容答案。普通题显示两张线索卡。BOSS 取两组共四张卡，两个答案分别按
  对应组的线索做兼容展开判定，并验证另外两种二分配对中每一种都至少有一侧
  不在池内。
- 格式塔排除部件包含 `𰀁`。`npm run build` 与 `npm run dev` 的预备步骤都会
  运行候选池分析，从当前拆字表与兼容层重新生成题库 JSON 和 CSV。
- 试炼 BOSS 的揭晓顺序以提交项为先，未提交项按题目顺序补足。仅格式塔
  BOSS 在全部答案答对后只展示实际提交的两项，不追加该部件对其他可接受解。
- 同一幕的答案字按幕去重。Gestalt 会同时排除包含本幕已用答案的部件对；
  各模式不再通过清空已用字集合来强行补题。
- 四张卡的 BOSS 部件区固定排成 2×2；其他数量继续沿用原分排规则。
- 双重曝光实现已保留在代码中作为休眠废案，但不再注册运行时规则或显示在
  调试选择器中；其生态位与预制件重复，且过度依赖辨认重叠字形。
- `TrialSession.inspectPool()` 可按普通题长度、BOSS 长度、
  BOSS 答案数、总部件数和逐拆法过滤函数返回题库可用性、长度桶与
  可行长度组合，用于进入阶段前发现空题库。
- 完整规则计划与归档入口见 `docs/trial-rules-plan.md`；原始意见及 UTF-8
  BOM 安全副本位于 `docs/archive/`。

## BOSS 验证

- 每次提交会搜索当前卡片中与规则允许部件数一致的切分，并验证所有
  已提交答案。
- 分步提交时，先接受任何能由当前卡片组成的合法答案，不预判剩余卡片
  是否还有解；玩家可随时撤回错误选择。
- 规则要求数量的答案全部提交后，只有答案卡全部耗尽才进入下一阶段。
  若仍有答案卡剩余，则显示错误反馈并停留在 BOSS，让玩家撤回后重试。
- 所有答案必须不同。
- 答案判定复用 `GameData.accepted()`，包括单向答案兼容展开。
- BOSS 结算作为一题记录，保存全部答案和完整部件顺序。
