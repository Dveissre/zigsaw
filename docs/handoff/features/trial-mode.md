# 试炼模式

索引：`docs/handoff/README.md`

## 状态

- 白模已完成，仅在 `/test/` 显示“试炼”入口。
- 正式 `/` 暂不显示试炼入口。
- 已接入无制限、四分法、急板、失与得、拾级、五个奇境变体、极简主义、
  短视、繁缛、心盲症共十四条规则定义。
- 已完成制限接入前的三项数据层准备：每题时限状态化、标准拆法/
  展示卡分离、规则兼容题库可用性预检。
- 实现位于 `feature/trial-mode`，未提交或推送时以 `git status` 为准。

## 已确认规则

- 共 7 个阶段。
- 每阶段 8 道普通题，随后 1 道 BOSS。
- 无制限普通题 30 秒，BOSS 90 秒；规则可覆盖时限。
- 使用通规一级、二级汉字。
- 普通题部件数概率：2 部件 15%、3 部件 42%、4 部件 23%、
  5+ 部件 20%。当前字库足够，不触发现有长拆法稀疏补偿。
- 无制限 BOSS 使用 6–8 张部件卡组成两个不同汉字。
- 无制限 BOSS 单字允许 2–6 部件，两字合计必须为 6–8 部件；
  规则可改变答案数量和总卡数。
- BOSS 答案不要求组成词语，但彼此不允许相同。
- 可以一次提交多个合法答案，也可以逐字提交并继续。
- 分步提交会立即移除第一个字使用的卡；此时可以撤销并恢复全部卡。
- 已消耗的卡保留空槽位，不重排其它卡片。
- BOSS 部件区右上角以斜线分数显示已成功组成的字数；错误提交不计数，
  撤销会减一。
- 已提交内容按字分行，每行以“部件卡｜汉字｜撤销图标”展示，可逐行撤回。
- 已消耗卡片保留固定槽位并变淡，其他卡片不重排。
- BOSS 顶部信息条首次进入时铺红并保持到 BOSS 结束，反馈刷新不重播。
- 超时立即结束试炼。
- 允许暂停。`/test/` 中沿用暂停时将剩余时间减半的测试行为。
- 暂停时圆环轨道闪红；恢复时卡片使用揭开动画。
- 中止或超时后先以红字揭晓答案，再由玩家点击“结算”进入结果页。
- 不保存中途进度；刷新或退出后不恢复本局。
- 遇到的汉字进入图鉴。
- Cris 奖励预留了结算字段和发奖入口，数值尚未确定；白模结算显示
  “奖励待定”，当前不实际增加 Cris。

## 规则数据

完整规则目录、依赖、实装批次和候选池分析见
`docs/trial-rules-plan.md`。原始意见表归档在 `docs/archive/`。

- `public/data/trial-rules.json` 是规则的权威数据，与显示名称解耦。
- 规则使用稳定 ID：`unrestricted`、`tetrarchy`、`presto`、
  `reschedule`、`inspissation`、`byland-water`、`byland-herb`、
  `byland-mount`、`byland-people`、`byland-speech`、`minimalism`、
  `myopia`、`compages`、`aphantasia`。中文名、英文名、说明和星级可以
  独立修改。
- 图标位于 `public/assets/trial-rules/<id>.svg`，文件名必须与规则 ID
  一致。
- 规则 JSON 使用 v2 结构，并分为：
  - `description.public`：玩家实际看到的准确说明；
  - `description.internal`：开发用完整效果；
  - `timing`：普通题与 BOSS 的基础时限和倍率；
  - `selection`：普通题和 BOSS 的部件数、答案数与总卡数约束；
  - `policy`：题面来源、判题兼容口径和展示卡形态。
- `src/game/trial-rules.ts` 在加载时校验 v2 文档、阶段绑定及关键枚举值；
  无效规则不会被静默降级。
- 普通题可通过 `partWeights` 指定固定长度权重，或通过
  `partWeighting: "pool"` 按当前题库分布抽取。
- 极简主义使用 `2:3 = 1:1`；繁缛按五部件以上的实时题库分布抽取。
- 当前测试档期写在 `stageAssignments`：
  - 第一幕：无制限。
  - 第二幕：四分法。
  - 第三幕：急板。
  - 第四幕：极简主义（测试页临时排期）。
  - 第五幕：短视。
  - 第六幕：繁缛。
  - 第七幕：心盲症。

调试解锁后，阶段开始页会显示“强制制限”选择器。选择结果保存在
`TrialState.forcedRuleId`，只覆盖当前幕的题库、时限、BOSS 结构与卡片策略；
进入下一幕时自动清空并恢复 `stageAssignments` 中的默认规则。选择
“按幕次”可立即撤销当前幕的覆盖。

左上角调试入口在首页、阶段页、游戏页和结算页均显示。若在计时游戏中首次
请求口令，游戏会先暂停，口令框关闭后再恢复；在阶段页解锁或撤销时会立即
刷新制限选择器。

## 实现结构

| 路径 | 职责 |
| --- | --- |
| `src/game/trial.ts` | 独立 `TrialSession`、题目池、BOSS 与计时 |
| `src/game/trial-rules.ts` | 规则类型、规则加载和幕次绑定 |
| `public/data/trial-rules.json` | 规则名称、星级、图标与效果数据 |
| `src/main.ts` | `/test/` 入口、阶段提示、游戏页和试炼结算 |
| `src/styles.css` | 模式开关、阶段提示、BOSS 与试炼结算样式 |
| `tests/trial.test.ts` | 阶段启动、BOSS、单字提交/撤销和超时测试 |
| `test/index.html` | `data-trial-test` 标记；只有此页开放试炼白模 |

试炼没有继续塞入 `GameSession`。后续阶段制限也应作为声明式规则接入
`TrialSession`，避免继续增加挑战模式的模式分支。

## 模式入口

- 正式页模式：挑战、练习。
- `/test/` 模式：挑战、试炼、练习。
- “无尽”不再是独立模式按钮，而是练习模式内的开关。
- 试炼入口在测试页的挑战和练习之间。
- 游戏和结算界面使用“第一幕”至“第七幕”；“阶段”仅作为内部或
  口头讨论用词。

## 规则前置数据层

- `TrialState.timeLimit` 保存当前题的原始时限。普通题和 BOSS 不再由
  界面根据阶段临时套用常量；计时环、平均用时和超时结算都读取该字段。
- 普通题的 `TrialQuestionState` 分离为：
  - `answerWay`：标准答案拆法。
  - `displayCards`：实际展示的带 UID 卡片，当前 `source = "answer"`。
- BOSS 的 `TrialBossState` 同时保存 `expectedWays` 与
  `initialCards/cards`，分别表示标准拆法和实际可操作卡片。
- 历史记录保存 `answerWay`、`displayCards`、标准部件名和展示部件名，
  供规则产生干扰卡、隐藏卡或万能牌后继续正确回放。
- 遮挡目标在出题时随机确定，并记录为卡片的 `obscuredAtMs`。累计有效
  答题时间达到阈值后设置 `obscured`；暂停冻结计时，恢复后不还原已翻黑卡。
- 翻黑通过 `obscure` 会话事件原地更新对应卡片的 DOM，不重绘整个游戏页，
  因此不会替换输入框或打断输入法候选栏。
- 翻黑卡从 DOM 移除字符、部件 ID 和可复制文本，但仍保留在会话卡片模型中，
  因而继续参与判题和答案消费。
- 失与得按幕维护共享时间池。普通题与 BOSS 都读取同一剩余值；答对后加
  5 秒并封顶 150 秒，进入下一幕时重新初始化为 150 秒。该规则暂停固定
  扣除 15 秒，覆盖测试环境默认的半时罚则。
- 拾级在进入阶段时生成整幕八题部件数路径。路径起点为 2，终点随机为 7
  或 8，只能不下降或单步增加 1；普通题依次按路径取题。BOSS 固定总卡数
  为 10，可分给两个不同答案。
- 终点先按 7/8 各自可用答案数加权；停留位置再按被重复长度的可用答案数
  加权。因此终点和停留位置都会随各部件数实际池体量倾斜，而不是固定等概率。
- 最近 12 个 7/8 部件汉字记录在
  `localStorage["zigsaw.trial.inspissation.recentLongChars"]`，新局优先
  避开这些答案；仅在候选池耗尽时回退。
- 奇境变体通过 `selection.excludedComponents` 排除整个成员类别；题面拆法
  使用逐拆法过滤，不只看整字是否仍有一条合法拆法。
- 普通题按 `decoyCount: 1` 加入一张 `source = "decoy"` 卡，BOSS 加入两张
  互不相同的干扰卡。允许干扰卡与答案卡组成其他汉字，但提交这些字判错。
- 正确答案揭示时，答案卡继续铺绿；干扰卡同时不铺绿、淡出并轻微模糊，
  原卡槽保留，避免其他卡重排。
- BOSS 判题只接受本题目标答案；`mustIgnore` 干扰卡允许剩余，不要求被答案
  消费。
- `TrialSession.inspectPool()` 可按普通题长度、BOSS 长度、
  BOSS 答案数、总部件数和逐拆法过滤函数返回题库可用性、长度桶与
  可行长度组合，用于进入阶段前发现空题库。
- 完整规则计划与归档入口见 `docs/trial-rules-plan.md`；原始意见及 UTF-8
  BOM 安全副本位于 `docs/archive/`。

## BOSS 验证

- 每次提交会搜索当前卡片中与规则允许部件数一致的切分，并验证所有
  已提交答案。
- 分步提交时，每个答案消费一组互不重叠的卡片，剩余卡片必须仍能
  切分为规则要求数量的答案。
- 提交完规则要求的最后一个答案时必须消费全部剩余部件。
- 所有答案必须不同。
- 答案判定复用 `GameData.accepted()`，包括单向答案兼容展开。
- BOSS 结算作为一题记录，保存全部答案和完整部件顺序。

## 结算

- 显示试炼完成或结束。
- 按幕分组回顾题目；大标题居中，答对数/总题数显示在标题下方。
- 每幕标题下方单独显示制限图标、名称和说明。
- 回顾卡片桌面每行 6 个、移动端每行 5 个，使用 1px 可见边框；
  BOSS 卡不跨格。
- BOSS 的每个答案拆成一张独立卡片，使用 EX-SSR 风格的紫色渐变底
  和浅色文字；卡片编号在幕内连续排列。
- 旧的绿底双字斜切拼合样式归档在
  `docs/archive/trial-boss-dual-card.css`，运行时不再加载。
- 所有回顾卡均可点击打开释义浮窗，包括 BOSS 的每个独立答案。
- 结果正文在内部滚动，页面本身不滚动；卡片按顺序入场并自动跟随滚动，
  鼠标滚轮使用外层回顾区域的原生滚动。
