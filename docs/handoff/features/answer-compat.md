# 答案兼容展开

索引：`docs/handoff/README.md`

## 状态

- 在 `bugfix/internal` 工作区实现。
- 保留原始拆法 `ways`，只增强答案判定。
- 未改变出题、挑战阶段、图鉴、收藏、部件统计或写字台候选。

## 目的

允许答案汉字使用更细粒度的兼容拆法，但禁止把规则反向用于题目。

数据文件：

```text
public/data/char_sym_answer_compat.json
```

格式：

```json
{
  "format": "zh-char-sym-answer-compat/1",
  "expansions": {
    "144": [[77, 5]],
    "77": [[1, 34]]
  }
}
```

`expansions` 的键是上位部件 ID，值是该部件的全部向下展开方案。每个方案是
一个部件 ID 数组。

## 判定语义

- 只允许候选答案从粗部件向细部件展开。
- 题目显示部件始终不展开。
- 一个部件有多种兼容方案时，任一方案成功即可。
- 兼容规则可以嵌套。
- 展开结果必须与题目部件多重集合完全相等；顺序无关，重复次数有关。
- 零次展开始终有效，因此原始拆法仍按原逻辑判对。

示例：

| 题目部件 | 输入答案 | 结果 | 原因 |
| --- | --- | --- | --- |
| `氵 + 大 + 丶` | 汱 | 正确 | `犬 → 大 + 丶` |
| `氵 + 犬` | 汰 | 错误 | 不允许反向把 `大 + 丶` 合为 `犬` |
| `氵 + 一 + 人 + 丶` | 汱 | 正确 | `犬 → 大 + 丶 → 一 + 人 + 丶` |

## 实现入口

| 路径 | 职责 |
| --- | --- |
| `src/game/data.ts` | 加载规则、验证 DAG、建立答案索引 |
| `GameData.accepted()` | 返回题目部件对应的全部可接受汉字 |
| `GameData.ways` | 原始出题拆法，兼容层不得修改 |
| `tests/data.test.ts` | 用真实字表验证汱/汰示例 |
| `tests/rules.test.ts` | 方向、嵌套、多方案、循环和出题隔离测试 |

运行时从题目部件反向搜索能通过向下展开得到该题目的原始答案拆法，再使用原有
部件集合索引查找汉字。这样不会把全部兼容拆法物化为新的 `ways`。

## 校验

- 规则和展开结果中的部件 ID 必须存在。
- 每条规则必须有非空展开方案。
- 兼容规则图不允许循环。
- 数据格式必须是 `zh-char-sym-answer-compat/1`。

## 其它分支如何使用

合并 `main` 后，不需要手工复制兼容规则。确认以下文件和测试一并存在：

- `public/data/char_sym_answer_compat.json`
- `src/game/data.ts`
- `tests/data.test.ts`
- `tests/rules.test.ts`

如果与其它分支同时修改了 `GameData.accepted()`，优先保留原始精确匹配，再合并
单向兼容索引；不要改成题目与答案都可互相归一化的等价匹配。
