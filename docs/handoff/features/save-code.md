# 紧凑存档码（beta）

索引：`docs/handoff/README.md`

## 定位

存档码是手机内建浏览器无法下载文件时的备用迁移方式，不是 `.zsave` 的替代。
有条件下载/上传文件时，仍优先使用主存档系统。

入口位于设置“存档”下一行的“存档码 (beta)”。点击“打开”后显示独立浮窗和
大文本框；点击“获取”生成代码并自动全选，按钮变为“复制”。用户也可以粘贴
代码后点击“导入”，成功解码后再显示一次覆盖确认。

## 存储内容

存档码不保存原始 localStorage JSON，而只保存恢复所需的最小领域状态：

- 已见汉字的 Unicode 码点集合
- 独立收集部件 ID
- 结构化挑战/无尽纪录；无法识别的旧键保留为 raw 条目
- Cris 余额
- 试炼最近长字（最多 100 个）

以下信息会从当前字表重建，不进入存档码：

- 每个汉字关联的部件 ID
- 表外汉字集合
- 图鉴 source hash
- 旧版 `zigsaw.collection.v1` 与旧纪录副本

## 编码格式

- 文本前缀：`ZSC1.`
- 正文版本：varint payload version，当前为 `1`
- 汉字：按 Unicode 码点排序，以相邻码点差值的 varint 编码
- 数字：无符号 varint
- 挑战纪录：难度、EX、题数、窗口、滑移、秒数和纪录值的结构化字段
- 完整性：正文经 AES-GCM 加密后与 12 字节 IV 拼接
- 外层：无换行 Base64URL；导入时会忽略粘贴产生的空白

当前实现不解码旧 `.zsave`；两者是并列入口。未来新增存档码正文版本时，
应在 `decodePayload()` 中增加旧版本迁移，不得改变历史版本语义。

## 导入流程

1. 读取文本框并忽略空白。
2. 校验前缀、Base64URL、AES-GCM 和正文结构。
3. 全部成功后显示“导入存档码？”确认浮窗。
4. 用户确认后，根据当前字表生成 collection v2、records 和 Cris 数据，
   通过 `.zsave` 的原子托管键替换逻辑写入。
5. 刷新页面重新加载各 store；取消确认不会修改任何数据。

## 体积与验证

- 用户提供的 694 字、5 条纪录、Cris=6407 的存档生成约 1,096 字符。
- 加密二进制本体约 819 字节。
- `tests/save-code.test.ts` 覆盖编解码往返、旧纪录键保真、根据字表重建、
  legacy 清理、未知外部键保留、损坏和伪格式拒绝。
- Playwright 覆盖“获取→复制”、取消导入不覆盖、确认导入后刷新恢复。
