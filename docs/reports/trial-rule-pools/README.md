# 试炼制限候选池报告

由以下命令生成：

```powershell
npm run analyze:trial-rule-pools
```

统计口径：

- 普通题库范围为通用规范汉字表一级、二级。
- 使用当前 `char_sym.json` 的全部可用拆法。
- 保留增补平面字符。
- 与 `GameData.isCharSelectable()` 一致，任一拆法含不可渲染部件时排除整字。
- CSV 使用 UTF-8 BOM，便于 Excel 直接打开。

文件：

- `inspissation-part-counts.csv`：2–8 部件汉字的字数与拆法数。
- `prefabrication-part-counts.csv`：3–10 部件答案中，至少有一对卡能直接合成
  另一个可渲染汉字的字数、拆法数、可用提示对数与提示字数。
- `gestalt-component-pairs.csv`：从答案原始拆法直接生成、排除指定常用部件后，
  排除两张部件卡本身可直接成字的整对，再保留直接生成答案数不超过 3 的部件对。
- `outland-composites.csv`：五类厄境的基础部件、附着部件组合及结果字。
- `summary.json`：总数、分类计数和 `char_sym.json` 来源哈希。

厄境结果字不限制在一二级字表，因为该字只用于干扰卡展示；基础部件仍限制为
正常试炼题中可出现的部件。

格式塔的候选部件对和生成答案都必须直接出现在原始答案拆法中，不会仅因
兼容层展开后出现而进入池。答案按字符去重。生成池排除：
一、丨、丿、丶、㇏、乚、亅、㇆、𠃊、𰀁、乛、二、十、冂、口。
若两张部件卡本身可以直接组成任意汉字，例如“丁 + 扌 = 打”或
“忄 + 隹 = 惟”，则整个部件对排除，即使它还能通过兼容层覆盖其他答案。
兼容层只在实时判题时展开提交字；例如生成池中的 `囗 + 五` 只列 `圄`，
但 `晤` 的原始拆法 `日 + 五 + 口` 展开 `日` 后同时包含这两张线索卡，因此
提交 `晤` 仍应判对。

预制件按直接拆法判断提示汉字：同一答案拆法中的两张卡必须恰好对应另一个
可渲染汉字的两部件拆法。提示汉字不限于一、二级字表；预组后按 symbol ID
比较，若结果等同于答案已有的任一拆法，则该预组方案被排除。
